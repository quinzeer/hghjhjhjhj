# APIs YouTube, TikTok et Claude Code headless — état vérifié au 28/09/2026

> Consulté le : 2026-09-28 · Auteur : researcher · Version : 1 · Portée : YouTube Data API v3 (quotas, upload, conformité, Analytics/Reporting), TikTok Content Posting API + mesure, Claude Code en mode headless (`claude -p`) sur abonnement Pro/Max sans clé API.

## Synthèse

- YouTube : les plafonds « 100 `videos.insert` + 100 `search.list` + 10 000 unités pour le reste » sont **toujours exacts** au 28/09/2026, mais la mécanique a changé deux fois : coût de `videos.insert` ramené de ~1600 à ~100 unités le 04/12/2025, puis, depuis le 01/06/2026, `videos.insert` et `search.list` ont chacun leur **propre bucket** de 100 appels/jour (1 unité/appel), séparé du pool de 10 000 unités [S1][S9].
- Le blocage en privé des vidéos uploadées par un projet API non audité créé après le 28/07/2020 est confirmé texto dans la doc officielle [S9][S10].
- `status.containsSyntheticMedia` existe depuis le 30/10/2024 [S9]. `status.selfDeclaredMadeForKids`, `status.publishAt`, `localizations`, `defaultAudioLanguage` sont tous documentés [S5]. Aucune API publique trouvée pour l'upload de pistes audio multilingues (fonctionnalité Studio uniquement) ni pour Test & Compare — cohérent avec la mission, mais absence de preuve, pas preuve d'absence [S18][S5][S6][S9][S10].
- TikTok : client non audité → `SELF_ONLY` obligatoire, comptes privés, max 5 utilisateurs autorisés à poster/24h ; 7 exigences UX précises listées pour Direct Post ; `is_aigc` (divulgation IA) et `brand_content_toggle`/`brand_organic_toggle` (contenu commercial) existent bien comme champs de l'API [S19][S20][S21].
- Claude Code headless : `--max-turns` **existe toujours** et est documenté dans `cli-reference`, malgré son absence de `claude --help` — la doc précise explicitement qu'un flag absent de `--help` n'est pas forcément indisponible [S26]. En mode `--bare`, Claude Code **ne lit jamais** les identifiants OAuth d'abonnement (confirmé texto) [S25][S26]. `claude setup-token` produit un jeton valable ~1 an [S28]. Si `ANTHROPIC_API_KEY` est définie et approuvée, elle prend le pas sur l'abonnement en mode `-p` (toujours utilisée, sans invite) [S28].
- Le changement de facturation de l'Agent SDK annoncé le 13/05/2026 pour le 15/06/2026 a été **suspendu le jour même** (« Nothing changes for now ») ; aucune nouvelle échéance retrouvée au 28/09/2026 dans les sources consultées [S38][S39]. La doc actuelle de Claude Code Docs continue de traiter `claude -p`/Agent SDK comme un usage normal de l'abonnement [S30][S32].
- YouTube compte désormais une vue dès le début de la lecture pour tous les formats (Shorts, long format, live) — règle **datée du 24/08/2026** dans la page d'aide officielle, donc très récente par rapport à la rédaction de la mission [S17].

## Conséquences d'architecture

- **Gestionnaire de quotas YouTube** : suivre 3 compteurs indépendants — bucket `videos.insert` (100 appels/jour, 1 unité/appel), bucket `search.list` (100 appels/jour, 1 unité/appel), pool partagé 10 000 unités/jour pour le reste (`videos.list`=1, `thumbnails.set`=50, `captions.insert`=400, `playlistItems.insert`=50, etc.). Ne jamais utiliser `search.list` pour la veille concurrentielle (coût élevé, quota séparé et limité) — privilégier `channels.list`/`playlistItems.list` sur les playlists d'uploads des chaînes connues, comme déjà prévu par la mission.
- **Audits à lancer tôt, et à distinguer** : (1) audit « YouTube API Services – Compliance/Quota Extension » (formulaire officiel, délai non publié — à mesurer) ; (2) vérification OAuth Google des scopes sensibles (`youtube.upload`, `youtube`, `youtube.force-ssl`, `youtubepartner`) pour sortir du statut « Testing » (refresh token à 7 jours) — dossier **distinct** de l'audit YouTube API ; (3) audit TikTok Content Posting API pour lever la restriction `SELF_ONLY` ; (4) vérification de compte/chaîne YouTube (téléphone) pour débloquer `thumbnails.set` côté UI, non documentée côté API elle-même — donc à tracer manuellement par chaîne, pas détectable via un simple appel API.
- **Champs à tracer par vidéo publiée** (registre de conformité/preuve, §4 divulgation) : `status.containsSyntheticMedia`, `status.selfDeclaredMadeForKids`, `status.publishAt`, `status.privacyStatus`, `localizations`, `defaultAudioLanguage` côté YouTube ; `is_aigc`, `brand_content_toggle`, `brand_organic_toggle` côté TikTok — avec horodatage et valeur exacte envoyée, pour la relecture `videos.list` après upload prévue en phase 5 et pour la porte de conformité.
- **Écart doc API / doc d'aide** : `thumbnails.set` n'expose aucun signal API de « compte non vérifié » dans sa documentation de référence ; le `compliance_officer`/`publisher` doit suivre le statut de vérification de chaque chaîne hors API (déclaratif, mis à jour manuellement), sous peine d'échecs d'upload de miniature non diagnosticables via le seul message d'erreur API.
- **Backend LLM (`ClaudeCodeRunner`)** : ne jamais passer `--bare` si l'authentification par abonnement est requise (le mode ignore silencieusement `CLAUDE_CODE_OAUTH_TOKEN` et tout OAuth) ; `make doctor` doit continuer à échouer dès que `ANTHROPIC_API_KEY` est définie dans l'environnement, même non utilisée intentionnellement, car sa seule présence approuvée une fois bascule la facturation ; privilégier systématiquement `--output-format json --json-schema <schema>` pour toute sortie devant être validée, avec repli Pydantic v2 + une relance bornée uniquement si le schéma ne suffit pas ; conserver `--max-turns` dans toutes les invocations malgré son absence de `--help` ; prévoir un détecteur de limite d'usage combinant code de sortie non nul et pattern-matching du texte d'erreur (`You've hit your session limit` / `...weekly limit` / `...Opus limit` / `...Sonnet limit`), faute de champ JSON structuré confirmé pour l'heure de reset en mode non interactif.
- **Routines Claude Code** si utilisées pour la veille/idées/scripts sans GPU (option par ADR du §6) : leur consommation s'ajoute à celle des sessions interactives de construction dans le même abonnement — le gestionnaire de quotas doit les additionner, et la fenêtre nocturne réservée au studio doit tenir compte du plafond quotidien d'exécutions de routines (valeur non publiée, à lire dans l'UI `claude.ai/code/routines`).
